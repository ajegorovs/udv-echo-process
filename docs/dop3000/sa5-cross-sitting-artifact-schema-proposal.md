# SA5 cross-sitting agreement artifact — closed schema proposal (v1)

> **Status: schema only; docs-only; no artifact, array, generator or value is committed here and
> none is generated by this PR.**
> This proposal fixes the **serialization contract** for the distinct cross-sitting agreement
> artifact that [`sa5-cross-sitting-agreement-prespec.md`](sa5-cross-sitting-agreement-prespec.md)
> (§1–§11, with amendment A1) reserves as "a separate, later, separately reviewed slice" (§9) and
> that the merged backend (`analysis/sparse_sa5_cross_input.py`,
> `analysis/sparse_sa5_cross_models.py`, `analysis/sparse_sa5_cross_core.py`,
> `analysis/sparse_sa5_cross_sitting.py`) emits today as **typed, in-memory records only** — the
> backend has **no writer**, publishes nothing and writes no file.
>
> This document is the cross-sitting analogue of
> [`sa5-effect-artifact-schema-proposal.md`](sa5-effect-artifact-schema-proposal.md) (the accepted
> **v1 contract**, cited below as *the v1 contract*). It **reuses** the v1 conventions unchanged
> where they apply (NPZ byte rule, strict-JSON discipline, CSV formatting, digest convention,
> publication/refusal gate, independent verifier) and **adds only** the serialization decisions the
> cross-sitting artifact needs. It decides **no scientific rule**: orientation, support, knot
> matching, definedness, every reduction and every typed-empty are already fixed by the prespec and
> implemented in the backend; this contract only says *where each number, state and reason is
> written and in what exact bytes*. Future scientific decisions are kept outside
> this schema and named in §14; none is invented here.
>
> It reuses **no observed value**: no agreement number appears in this document, and none is read
> to write it. The two committed v1 quartets (`sa5-live-1-effects.*`, `sa5-live-2-effects.*`) and
> every frozen WP/SA2.4 report stay byte-untouched.

## 1. Products, naming and ownership

One artifact set of four files under the plan's publish root `reports/sparse-signal/` (v1 contract
§1), with the stem `sa5-cross-sitting`:

| file | content |
| --- | --- |
| `sa5-cross-sitting.npz` | the per-comparison per-knot arrays (§3, §4) |
| `sa5-cross-sitting.json` | identity, the two source quartets' digests, the typed states and reasons, the frozen per-side context quotations, the non-value rows and the digests (§5) |
| `sa5-cross-sitting.csv` | the 72-row one-row-per-comparison **scalar set** — the sole home of every comparison reduction (§6) |
| `sa5-cross-sitting.README.md` | units, definitions, the two source quartets' digest chains, the regeneration command and the no-go list (§7) |

`schema` is the new closed id **`sa5-cross-sitting/v1`** (the source quartet's own id stays
`sa5-within-sitting-effects/v1`). The artifact is **one comparison**, `live2 − live1`
(`ORIENTATION = "live2 - live1"`), never a per-sitting file and never a third sitting. Stage-2
(`stage2-e20-e64/`) is context, is not a sitting, and is never bound (prespec §1). A generator
accepts **no argument but the publish root**: the two sides are the two fixed reproducibility
sittings, selected by name through the input layer **from the committed source
quartets under the repository's `reports/sparse-signal/`, independent of
`--report-dir`**. A scratch `--report-dir` redirects outputs only; it never
redirects reads to quartets copied into the output directory. The reversed
orientation refuses (prespec §10).

## 2. Cardinality, the comparison key and the frozen order

The row set is the backend's **72 comparisons** over the frozen keys `(view, metric,
contrast-or-interaction)` — nine `(metric, view)` endpoints, each carrying the seven bound
contrasts plus `pitch_x_burst_interaction` (v1 contract §2; prespec §2). The `effect_id` is the
join `"<view>__<metric>__<contrast>"`; a reader **resolves it through the JSON `comparisons`
list and never parses the string** (v1 contract §2).

**Order is fixed and identical in the JSON `comparisons` list and the CSV rows**: endpoint order
(`sparse_sa5_effects.ENDPOINTS`), then the seven bound contrasts in `CONTRASTS` order, then the
interaction — exactly `sparse_sa5_cross_input.comparison_keys()`. The NPZ members are ordered by
ascending lexicographic **member name** (§4.3), not by this order.

`grid` is a **function of the contrast**, asserted not chosen (prespec §2,
`sparse_sa5_cross_input.expected_grid`): corner contrasts and the interaction are `corner_knots`;
the three `E*_minus_E20` contrasts are `emissions_knots`.

## 3. The NPZ — closed per-comparison member set, dtypes, masks, states

`sa5-cross-sitting.npz` is a ZIP of NumPy `.npy` members (v1 contract §3–§4). A **comparable**
comparison (the backend's `ComparisonState.COMPARABLE`) has a comparison domain of `Kc ≥ 1` knots
— the native knots that lie **inside both sides' support intersection** (prespec §3,
`core.within_support` / `core.restrict`) — and contributes exactly **five** members,
prefix-qualified by its effect id:

| member name | dtype | shape | meaning |
| --- | --- | --- | --- |
| `<effect_id>__knots_mm.npy` | `<f8` | `(Kc,)` | the comparison knot depths, strictly increasing |
| `<effect_id>__difference.npy` | `<f8` | `(Kc,)` | the oriented difference `D = E2 − E1` where defined, the finite placeholder `0.0` where not |
| `<effect_id>__defined.npy` | `<u1` | `(Kc,)` | the common-defined mask `D`: `1` exactly where **both** sides are defined, else `0` |
| `<effect_id>__state1.npy` | `<u1` | `(Kc,)` | the **live-1** effect state code (table A, §5.4) |
| `<effect_id>__state2.npy` | `<u1` | `(Kc,)` | the **live-2** effect state code (table A, §5.4) |

There is **no other member**. `Kc` is not a stored member: it is the array shape, and the JSON
publishes `comparison_knot_count = Kc` (§5.3), so the shape is stated in two places and must agree
exactly (v1 contract §3 precedent).

### 3.1 A non-comparable comparison contributes no member

A comparison that is `not comparable` has **no common comparison domain** (prespec §7): the pair
shares no structural basis or no common defined knot. It therefore contributes **zero** members —
it is described entirely by its JSON record and its CSV row. **Zero-length members are never
written** and the reader refuses a `(0,)` member, because an empty array would invent a comparison
domain that does not exist (v1 contract §4 point 5, "a refused artifact, not a warning"). Which
comparisons are comparable is a deterministic property of the two published quartets, so the member
set is deterministic and is published exactly by the JSON `npz_members` list (§5.5).

### 3.2 The pair's states are published, the two oriented effect profiles are not

The prespec §4 requires the comparison's own per-knot state pair `(state2[k], state1[k])` be
**published beside** each comparison knot. This contract publishes it as the `state1`/`state2`
code arrays — the pair is the comparison's **join/refusal metadata** (which side refused and why),
mirrored from the sides' own `state` codes and checked for exact agreement (§12), not a second
scientific reduction (v1 contract §5, "structural identity, shape and join metadata … may
mirror").

The two sides' **oriented effect values** `E1(z)`, `E2(z)` are **not** re-published as members.
They are the frozen quartets' own per-knot values, whose single home is each side's
`sa5-live-N-effects.npz` under its own digest chain; a copy here would be a second home for a
within-sitting value the cross artifact must not re-derive (prespec §9, "never overwrite or
re-derive a v1 within-sitting value"). The cross artifact's **new** per-knot quantity is the
difference `D`, and `D` is its member. A reader (and §12's verifier) obtains `E1`/`E2` from the
same digest-bound quartets the comparison was computed from; `D` is recomputed as `E2 − E1` on the
published comparison knots. *(This placement is a deliberate serialization choice, flagged in §14
as re-openable; it is not a scientific claim.)*

### 3.3 Placeholder, mask and state discipline (inherited)

The tables are closed and the discipline is the v1 contract §3.2 / §8 one, restated for the pair:

- `state1[i]`/`state2[i]` are the codes of table A of §5.4 (`0` `defined`, `1`
  `undefined-operand`, `2` `undefined-alignment`); a code outside the table is a refused artifact.
- `defined[i] == 1` **exactly** where `state1[i] == 0` and `state2[i] == 0`, and `0` at every
  other position — the prespec §4's `D = { k : defined2[k] = 1 and defined1[k] = 1 }`.
- Every undefined position of `difference` carries the **finite placeholder `0.0`**; a non-finite
  number, an object or a NaN is a refused artifact (`allow_pickle=False` reading is exact).
- `knots_mm` is strictly increasing; every float is finite; every mask value is exactly `0` or `1`.
- An `undefined-alignment` side is the engine's "no native gate lay within half the knot pitch"
  sentinel and is **never** a `0.0` measurement (prespec §4).

## 4. The canonical NPZ byte rule

The rule is the v1 contract §4, applied unchanged; it is restated here so the contract is closed:

1. **Container.** One `zipfile.ZipFile(path, "w", compression=zipfile.ZIP_STORED,
   allowZip64=False)`; every member **stored, never compressed**.
2. **Fixed timestamps and attributes.** Every member written through an explicit
   `zipfile.ZipInfo(name, date_time=(1980, 1, 1, 0, 0, 0))` with `compress_type=ZIP_STORED`,
   `external_attr=(0o600 << 16)`, `internal_attr=0`, `create_system=0`, `extra=b""`,
   `comment=b""`. No archive comment and no directory entries.
3. **Sorted members.** Members written in **ascending lexicographic member-name order**, so the
   central-directory order is fixed by the schema and not by dictionary iteration.
4. **Fixed member format.** Each payload is a `.npy` written by
   `numpy.lib.format.write_array(buf, array, version=(1, 0), allow_pickle=False)`, **C-contiguous**
   and of the member's exact **fixed little-endian** dtype (`<f8`, `<u1`) — the byte order is in
   the dtype, so a big-endian host produces the same bytes. Only those two dtypes occur.
5. **No pickling, no extras.** A member name outside the closed five suffixes, a duplicate member,
   a payload whose declared dtype/shape/order is not §3's, a `(0,)` member, or any non-finite
   value is a **refused artifact**, not a warning.
6. **The digest is the actual SHA-256 of these bytes** (§5.6), computed from the file this run
   staged, never from a copy regenerated beside it.

## 5. The JSON — closed fields, states, non-value rows, digests

`sa5-cross-sitting.json` is **strict JSON** by the v1 contract §5 rule: UTF-8, `ensure_ascii=True`,
`sort_keys=True`, `separators=(",", ":")`, **`allow_nan=False`** (a non-finite value fails the run
before any byte is written), LF endings and exactly one trailing newline. Its field set is
**closed** — a new field is a schema change, not a new value. It carries **no ndarray** (issue #49
remains open) and **no comparison reduction number**: every comparison scalar is the CSV's (§6).

**The one-home rule for this artifact.** Every **comparison reduction and cross-sitting number**
has exactly one home: the **CSV**. The **NPZ** holds the per-knot comparison arrays. The **JSON**
holds identity, the two sides' provenance digests, the closed vocabularies, the typed-empty rows
and the two sides' **context quotations** (§5.4) — and **no** comparison reduction. Per-knot data
is never placed in the JSON or the CSV; a comparison scalar is never placed in the JSON.

### 5.1 Top-level fields (closed)

```
schema                 "sa5-cross-sitting/v1"
ok                     bool   (§10)
checks                 object: the comparison run's own named checks → bool (closed set, §5.2)
artifact_checks        object: the schema-level checks on the staged bytes → bool (closed set, §5.2)
comparison             "live2 - live1"   the fixed orientation string
sitting1               "live-1"
sitting2               "live-2"
analysis_commit        string
generator_revision     string
generator_command      string   the exact regeneration command (§7)
provenance             object: {"live-1": <SideProvenance>, "live-2": <SideProvenance>} (§5.4)
state_meanings         object: {"effect": [{"code": 0|1|2, "text": ...}, ...]}   (§5.4)
comparisons            list of 72 comparison records, in the frozen order (§2), key set §5.3
npz_members            sorted list of every NPZ member name (§5.5)
nonvalue_rows          list of typed-empty rows (§5.6), in the frozen order
nonvalue_counts        object: {state: {kind: count}} (§5.6)
limitations            list of strings, the run's own limitation statements, quoted verbatim
weighting_rule         string   the engine's trapezoidal rule text, quoted
method                 string   the engine's method text, quoted
artifacts              object: <the cross set's own digests>, keys only npz, csv (§5.7)
```

### 5.2 The two closed check sets

`checks` is the comparison run's own check map, **copied verbatim** from
`sparse_sa5_cross_sitting.compare_cross_sitting`, and is **closed** to its nine names:

`no_output_artifact_written`, `fixed_orientation_live2_minus_live1`, `seventy_two_comparisons`,
`every_effect_id_resolves_in_both_sittings`, `comparison_and_label_states_kept_separate`,
`no_label_but_deferred_pending_review_is_written`, `no_recurrence_verdict`,
`repeat_context_identity_fully_established`,
`repeat_context_state_isolated_from_comparison_and_label`.

`artifact_checks` is the schema-level set, computed on the bytes this run staged, and is closed to
its six names:

`npz_members_are_the_closed_set`, `every_comparison_position_carries_its_mask_and_state`,
`comparison_rows_are_the_frozen_order`, `no_comparison_scalar_lives_outside_the_csv`,
`source_quartets_are_byte_unchanged`, `digests_match_the_staged_bytes`.

`ok` is the **structural** verdict (§10): true exactly when every `artifact_checks` entry is true
**and** every `checks` entry is true **except** `repeat_context_identity_fully_established` — the
ancillary repeat-identity check is published but is not part of `ok`.

### 5.3 A comparison record (closed key set, "key shapes")

```
{
  "effect_id":              "<view>__<metric>__<contrast>",
  "view":                   "primary-comparison" | "full-record",
  "metric":                 "mean"|"std"|"mad_scaled"|"recurrence-1e-lag"|"recurrence-peak-lag"|"band_fraction",
  "contrast":               <one of the seven bound contrast names> | "pitch_x_burst_interaction",
  "grid":                   "corner_knots" | "emissions_knots" | null,
  "units":                  "mm/s" | "s" | "dimensionless" | null,
  "knot_count":             int | null,     // the mirrored source K (structural identity, §2)
  "comparison_knot_count":  int | null,     // Kc, the (Kc,) member shape (§3)
  "participant_count":      int | null,
  "support_mm":             [low, high] | null,   // the two sides' support intersection
  "comparison_state":       "comparable" | "not comparable",
  "comparison_reason":      string,                 // verbatim, §5.3.1
  "label_state":            "deferred-pending-review" | null,
  "context1":               <SideContext> (§5.4),   // always the live-1 quotation
  "context2":               <SideContext>            // always the live-2 quotation
}
```

`knot_count` is the source quartet's published `knot_count` (part of the structural identity the
prespec §2 requires to agree exactly on both sides); `comparison_knot_count = Kc` is the number of
comparison knots inside the support intersection and is the `(Kc,)` shape the NPZ is checked
against. They are distinct and both published. For a `not comparable` pair, `comparison_knot_count`
is `null` and the pair contributes no NPZ member (§3.1). `support_mm` is `null` where no
intersection exists.

#### 5.3.1 `comparison_state` and `comparison_reason`

`comparison_state` is a **closed three-name vocabulary** (`ComparisonState`:
`comparable` / `not comparable` / `not resolvable with this design`). The v1 writer emits only the
first two: `not resolvable with this design` requires a separately reviewed endpoint-specific rule,
none is registered, and the backend raises rather than emit it (prespec §7–§8); the artifact check
refuses such a row if it ever appears. `comparison_reason` is the backend's own reason text,
**copied verbatim, never re-tokenized** (a re-tokenization would be a new rule). The closed set of
values that can appear is exactly:

- `comparable` → `common-basis-established`;
- `not comparable` → one of `effect-id-mismatch`, `triple-mismatch`,
  `grid-mismatch-pending-review`, `units-mismatch`, `side-wholly-undefined`,
  `empty-common-support`, or the one templated string
  `side-effect-not-published: the effect is not published on {live-1|live-2}, so the pair is not matched`.

`label_state` is **`deferred-pending-review`** for a `comparable` pair and **`null`** otherwise; no
other value is ever written (prespec §8). `comparison_state` and `label_state` are separate axes
and neither is ever written into the other's field.

### 5.4 The two shared blocks

**`state_meanings`** is published **once** at top level, the effect table A of §3.3/§8 (three
`{"code", "text"}` rows), so a `state1`/`state2` code is never ambiguous and the code lives in the
NPZ while the text lives in the JSON (v1 contract §8).

**`provenance`** is `{"live-1": <SideProvenance>, "live-2": <SideProvenance>}`, each a closed
record mirroring `sparse_sa5_cross_models.SideProvenance`:

```
{
  "sitting":            "live-1" | "live-2",
  "pass_name":          "sparse-mixer-live-1" | "sparse-mixer-live-2",
  "plan":               string,
  "plan_fingerprint":   bare 64-hex lowercase,
  "stem":               "sa5-live-1-effects" | "sa5-live-2-effects",
  "json_sha256":        "sha256:<64-hex>",   // the side's JSON, canonical LF
  "npz_sha256":         "sha256:<64-hex>",   // the side's NPZ, exact bytes
  "csv_sha256":         "sha256:<64-hex>",   // the side's CSV, canonical LF
  "checks_ok":          bool,   // the side's own checks all true
  "artifact_checks_ok": bool    // the side's own artifact_checks all true
}
```

Each of `json_sha256`/`npz_sha256`/`csv_sha256` is **recomputed by the input layer from the
published bytes** (`FrozenQuartet.digests`) and cross-checked against the side's JSON
`artifacts.*.sha256`; the cross JSON records the recomputed tokens, which the input layer has
already verified equal the side's own README→JSON→NPZ/CSV chain (prespec §1, §10). `bare 64-hex
lowercase` (`plan_fingerprint`) is never prefixed.

**`SideContext`** (the §6 frozen context quotation) is a closed record mirroring
`sparse_sa5_cross_models.SideContext`:

```
{
  "sitting": "live-1" | "live-2",
  "units": "mm/s"|"s"|"dimensionless"|null,
  "rms_magnitude": null|number, "signed_depth_average": null|number,
  "equal_knot_average": null|number,
  "max_abs_value": null|number, "max_abs_depth_mm": null|number,
  "covered_depth_mm": null|number, "coverage_fraction": null|number,
  "defined_count": null|int, "undefined_alignment_count": null|int,
  "undefined_operand_count": null|int, "knot_count": null|int,
  "repeats": [ <RepeatContext>, ... ]
}
```

Every scalar here is a **verbatim quotation** of the side's own published CSV cell (the backend
reads the side's CSV row); it is **context only** — the prespec §6 requires it be published
**beside** the comparison — and it is **never** a comparison decision and **never** this
artifact's reduction. The verifier checks each quoted value equals the side's CSV cell exactly
(§12), so a quotation cannot drift. Because it is a quotation under the side's digest, the same
number may legitimately appear in the source quartet and here; the one-home rule of §5 governs
**this artifact's own** comparisons, not a labelled quotation of a source.

**`RepeatContext`** (the §6 per-operand repeat context) is a closed record mirroring
`sparse_sa5_cross_models.RepeatContext`:

```
{
  "operand":          one of the operand labels of §5.3's contrast (e.g. "cc1", "E20", "e8"),
  "clause":           "unavailable" | "common-reference" | "block-local-anchor",
  "state":            "selected" | "repeat-context-unavailable" | "repeat-context-identity-unverifiable",
  "group_condition":  string|null,     // the published group's own condition text, quoted, never parsed
  "members":          [ {"label": s, "order": i, "job": s, "value": null|num,
                         "defined_count": i, "state": null|s, "reason": s}, ... ],
  "identity_verified": bool,
  "identity_basis":    string,         // the backend's own basis text, quoted verbatim
  "reason":            string          // the backend's own reason text, quoted verbatim
  // "min_value","max_value","spread" appear ONLY when state == "selected" (see below)
}
```

**The numerical range keys are state-conditional.** `min_value`, `max_value` and `spread` are
present **iff `state == "selected"` and identity is proved**; for
`repeat-context-unavailable` and `repeat-context-identity-unverifiable` the three keys are
**omitted entirely — not null, not `0`** — so no numerical range can be read against an operand
whose whole achieved condition is not proved equal to the group's (amendment A1, prespec §6).
`members` and `group_condition` are still published for a named group (the unverifiable case),
because the group is named and its members quoted; only the **range** is withheld. A `selected`
context carries `identity_verified = true`; the two typed-empty states carry
`identity_verified = false`. The validator forbids numbers on a non-selected context and forbids
members/identity on an `unavailable` one (backend `RepeatContext._check_the_typed_state_is_its_evidence`).

### 5.5 `npz_members`

The **sorted list of every member name** in `sa5-cross-sitting.npz` (§3, §3.1): the five suffixes
of each **comparable** comparison, globally sorted ascending. A reader checks the container's
member set equals this list exactly (no extra, no missing, no duplicate) and that every name is
`<effect_id>__<suffix>.npy` for a suffix in the closed five.

### 5.6 Typed-empty rows (`nonvalue_rows`) and `nonvalue_counts`

`nonvalue_rows` records each comparison **scalar position whose value is missing because the
comparison could not carry it** — the typed-empty set, not the refusal set. Following the v1
contract §5.5 precedent, a scalar whose emptiness is **derivable from the CSV's own coverage
fields is not a nonvalue row**: empty `signed_depth_average`/`rms_difference` (readable from
`covered_depth_mm == 0`), empty `coverage_fraction` (readable from `comparison_knot_count == 1`),
and empty `sign_agreement` (readable from `sign_count == 0`) are left to the CSV alone. A
nonvalue row is published only where the reason is **not** derivable from a CSV count — the shape
refusal and the localization refusals:

```
{ "effect_id": <key>, "kind": "shape"|"peak"|"peak-displacement",
  "side": null | "live-1" | "live-2", "state": <closed token>, "reason": <verbatim text> }
```

- `kind = "shape"` — `shape_correlation` is empty. `state` is the JSON-only token
  **`undefined-shape`** (v1 contract §5.5); `side` is `null`; `reason` is the backend's
  `Diagnostics.shape_reason` text, copied verbatim.
- `kind = "peak"` — a side's `peak_localized_s` is **false**. `side` names the failing side
  (`live-1` or `live-2`); `state`/`reason` are the backend's `peak_reason1`/`peak_reason2`
  (`insufficient-depth-support` or `constant-absolute-effect-profile`), copied verbatim. Two rows
  may appear when both sides fail.
- `kind = "peak-displacement"` — `peak_displacement` and `peaks_coincide` are empty.
  `side` is `null`; `state`/`reason` are the backend's `peak_displacement_reason`, copied verbatim.

A `not comparable` comparison contributes **no** nonvalue rows: its pair-level state and reason
live in its comparison record (§5.3). `nonvalue_counts` is the nested `{state: {kind: count}}`
object; the counts sum to the number of `nonvalue_rows`.

**Rows are ordered deterministically**: by the frozen comparison order (§2), and within a
comparison by `kind` in the fixed order `shape`, `peak` (with `live-1` before `live-2`),
`peak-displacement`.

### 5.7 Digests — the convention

The v1 contract §5.7 convention, applied identically:

- `artifacts.npz.sha256` is `"sha256:" + SHA-256(<the NPZ's exact file bytes>)` (the container is
  already canonical by §4; no normalization).
- `artifacts.csv.sha256` is `"sha256:" + SHA-256(<the CSV's canonical LF bytes>)`
  (`analysis._floor_documents.table_digest`: `read_bytes().replace(b"\r\n", b"\n")`).
- Both are recorded in the JSON as nested `artifacts: {"npz": {"file": "sa5-cross-sitting.npz",
  "sha256": ...}, "csv": {"file": "sa5-cross-sitting.csv", "sha256": ...}}`, each with its sibling
  file name. The **JSON's** own digest is recorded in the README (§7). A file never carries its own
  digest.
- Every digest is lowercase hex with the `sha256:` prefix. A source digest (`source_sha256`) is
  bare 64-hex lowercase; a `plan_fingerprint` is bare. `nonvalue_counts` and every reduction are
  not digests.

## 6. The CSV — the one per-comparison scalar row set

`sa5-cross-sitting.csv` has **one row per comparison (72 rows)**, in the frozen §2 order, keyed
`effect_id`. It is the **sole** home of every comparison reduction; the JSON does not repeat any of
these. Columns, closed and in order (30 columns):

```
effect_id, view, metric, contrast, units, grid,
knot_count, comparison_knot_count, defined_count, sign_count,
span_mm, covered_depth_mm, coverage_fraction,
signed_depth_average, rms_difference,
positive_count, negative_count, zero_count, sign_agreement,
zero1_count, zero2_count, shape_correlation,
peak1_value, peak1_depth, peak2_value, peak2_depth,
peak_localized1, peak_localized2, peak_displacement, peaks_coincide
```

These are the backend's `Diagnostics` scalars (`sparse_sa5_cross_core.Diagnostics`) plus the
mirrored structural keys and counts. Their meanings, exactly as the prespec and backend define
them, are: `knot_count` the mirrored source `K`, `comparison_knot_count` `Kc`, `defined_count`
`|D|`, `sign_count` `|S|`, `span_mm` the comparison span (last knot − first knot, `0.0` when
`Kc == 1`), `covered_depth_mm` `L` (the depth of adjacent comparison-knot pairs whose **both**
endpoints are defined), `coverage_fraction = L / span` (empty when `span == 0`),
`signed_depth_average` `D̄` and `rms_difference` `RMS(D)` (each empty iff `L == 0`),
`positive_count`/`negative_count`/`zero_count` (over the defined difference values; sum to
`defined_count`), `sign_agreement` `A_sign` (empty iff `|S| == 0`), `zero1_count`/`zero2_count`
(the per-side defined-zero counts), `shape_correlation` (empty on a shape refusal — its reason is
the JSON `shape` nonvalue row), `peak1_*`/`peak2_*` (each side's numerical maximum and its shallower
depth, defined whenever `|D| ≥ 1`), `peak_localized1`/`peak_localized2` (the localization
booleans), `peak_displacement = z*_2 − z*_1` (positive = deeper in live-2) and `peaks_coincide`
(both present only when both sides are localized).

**`Diagnostics.shape_defined_count` is not serialized.** The backend carries two defined counts on
one `Diagnostics` (`sparse_sa5_cross_core`): `defined_count` — the common-defined count `|D|` — and
`shape_defined_count`, the number of common defined knots the Pearson shape correlation used. In v1
these are the **same count** on every comparison: the backend constructs the record as
`defined_count=count` and `shape_defined_count=count` from one and the same `count` (the number of
positions where the common-defined mask is `1`), and the shape correlation is attempted only over
those `|D|` knots. The schema therefore gives the second count **no home of its own**: no
`shape_defined_count` CSV column exists (the 30 columns above are the closed set), no JSON field and
no NPZ member carries it, and its only value is the **`defined_count` already published at
`|D|`**. §12's verifier checks the equality explicitly — the recomputed `Diagnostics` must satisfy
`shape_defined_count == defined_count == |D|` — and refuses the artifact if a run ever emits them
unequal. Publishing the second count separately, or widening this column set, would be a schema
change, not a schema-compatible value.

**Formatting, inherited from the v1 contract §6:**

- an undefined scalar is the **empty field**, never `0`;
- every finite float is `format(value, ".17g")` (round-trip decimal for binary64), no display
  rounding left to the generator;
- an integer cell is `str(int)`;
- booleans are serialized as §8;
- UTF-8, RFC 4180 quoting as needed, `\n` row terminators, exactly one trailing newline;
- a non-comparable row keeps its structural identity cells where they are known and leaves every
  reduction, boolean and (where unknown) identity cell empty; its state and reason are read from
  the JSON.

The `weighting_rule` and the method text are definitions and are in the JSON; the CSV carries the
number.

## 7. README — definitions and binding

`sa5-cross-sitting.README.md` states the orientation (`live2 − live1`), the units and definitions of
every column, member and typed state, the trapezoidal weighting rule, the two source quartets and
**their** digest chains, the two views' differing duration/resolution/Nyquist, the regeneration
command, the structural-vs-ancillary `ok` rule (§10) and the no-go list. It binds its own claims to
the cross files by digests — including **`artifacts.json.sha256`**, the cross JSON's canonical-LF
digest, which is the reader's entry point to the chain
(`cross README → cross JSON → cross NPZ + cross CSV`, and `cross JSON.provenance → each source
quartet → its own README → its JSON → its NPZ + CSV`). It does **not** interpret a repeat range as a
floor, does not rank conditions, and publishes **no recurrence verdict**.

The regeneration command follows SA2.4's writer shape and is module-invoked, e.g.
`python -m udv_echo_process.analysis.<cross-sitting-writer-module> --report-dir <path>`; the exact
module name is fixed when the writer slice lands and is recorded in `generator_command`.

## 8. Boolean serialization

- **JSON**: `true` / `false` (JSON literals). A typed-empty boolean is the JSON literal `null`.
- **NPZ**: masks and codes are `<u1` integers (`defined` `0`/`1`; `state1`/`state2` table-A codes).
  A boolean dtype, a mask value other than `0`/`1`, or a state code outside table A is a refused
  artifact.
- **CSV**: the boolean columns `peak_localized1`, `peak_localized2`, `peaks_coincide` render the
  lowercase tokens **`true`** / **`false`** (never `True`/`False`, never `1`/`0`); a typed-empty
  boolean is the **empty field** (never `null`, which is not a CSV token). A writer refuses a
  Python `bool` reaching a numeric or count cell (v1 contract §6 `_cell_text` precedent).

## 9. Signed zeros

The artifact fixes one rule, so two runs and an independent recomputation agree bit-for-bit:

- **No signed-zero normalization.** The stored `difference` is the IEEE-754 binary64 result of
  `E2 − E1` exactly as the backend computes it; a `−0.0` is written as `−0.0` and **never**
  silently rewritten to `+0.0`. Normalizing would make the artifact disagree with a verifier that
  recomputes the raw IEEE difference, which is precisely what §12 must be able to do.
- **`−0.0` is numerically zero.** For every comparison, count and fraction, `−0.0 == 0.0`; a
  `−0.0` difference counts in `zero_count` and is never negative, exactly as `float("−0.0") < 0.0`
  is false (backend counts `gaps == 0.0`).
- **A `−0.0` occupies no undefined position.** Undefined positions carry the placeholder exactly
  `+0.0`; so a `−0.0` in `difference` is unambiguously a **defined** value (and every position is
  governed by `defined`, not by the sign of the value).
- **Text rendering.** `format(−0.0, ".17g")` is the CSV token `-0`; `format(0.0, ".17g")` is `0`.
  The sign is preserved so a reader sees it; it changes no count.
- No state code, knot depth or count ever carries a signed zero.

## 10. Structural `ok` vs the ancillary repeat-identity check

Two things must not be conflated (prespec §6, §9; backend `CrossSittingComparison.ok`):

- **`ok` is the structural verdict**: all six `artifact_checks` **and** all `checks` entries true
  **except** `repeat_context_identity_fully_established`.
- **`repeat_context_identity_fully_established` is ancillary**: it is **false** whenever any
  operand's §6 repeat context is `repeat-context-identity-unverifiable`. That happens for the
  `e8`/`e64`/`e128` anchors (their block-local anchor groups' `ctrl-*` members carry no achieved
  condition), and it is a property of *context*, not of the comparison. It is published as `false`
  and it does **not** make `ok` false.
- Consequently a run can and does publish `ok: true` with
  `checks.repeat_context_identity_fully_established: false` and a `limitations` entry naming the
  unverifiable operands. The repeat context is **excluded from every comparison decision**: it can
  never produce a `comparison_state`, a `label_state` or a reduction (prespec §6; the run check
  `repeat_context_state_isolated_from_comparison_and_label` asserts it).
- A pair whose repeat context is `repeat-context-unavailable` or
  `repeat-context-identity-unverifiable` is **still `comparable`**, with identical
  `comparison_state`, `label_state` and diagnostics to the same pair with a selected context
  (prespec §11.10).

## 11. Publication and refusal gate (idempotent / refusal policy)

The v1 contract §9 gate, applied to the cross set:

- Stage every file beside its destination under a unique, fsynced temporary name and move it onto
  its final name with one `os.replace` at a time. The set is **not** a transaction; a digest
  mismatch is what a reader detects, not a rollback. Refuse to overwrite an existing file this
  writer did not produce, and refuse a stage file or a lock an interrupted run left behind.
- **Idempotent:** if **all four** files already exist and their bytes match this run's fully staged
  products, publication does nothing. **Refuse:** if any file is missing or differs, refuse without
  replacing any existing file — for an incomplete set, a mixed set left by an interrupted run, or
  an unrelated file bearing the cross stem. The sibling SA2.4 files and the two v1 quartets are
  never candidates for replacement.
- **Refuse the whole run** (the input/backend gate, prespec §10) for: a side outside the two
  reproducibility sittings; a missing/unreadable file; a broken digest chain (README ↛ JSON,
  JSON ↛ NPZ/CSV); a side not `ok` or whose own `checks`/`artifact_checks` do not re-assert true; a
  container the codec refuses; a duplicated or drifted effect id; a container/CSV effect set not
  equal to the document's; the reversed orientation `live1 − live2`; a third sitting or Stage-2 as
  an input; a §6 mapping whose named group is absent or ambiguous (a publication defect, never a
  narrowed mapping); a `not comparable` pair carrying a `label_state`; or a `not resolvable`
  outcome (no rule registered). A **broken chain or failed input gate refuses the whole run**, not
  merely a row; a defined pair with a typed-empty diagnostic stays `comparable`.
- **Refuse the artifact** at the byte level for: a member outside the closed five, a `(0,)` member,
  a mask/state outside the closed tables, a non-finite number, a boolean reaching a numeric cell, a
  `not resolvable` row, a per-knot value found in the JSON or the CSV, a comparison scalar found in
  the JSON, or a `source_quartets_are_byte_unchanged` failure.
- Generate **nothing** unless the whole gate holds: no partial set, no scalar without its home, and
  never a cross-sitting value written into a v1 quartet or a frozen WP/SA2.4 report.

## 12. The independent verifier

The verifier is a separate program that **does not read the writer's staged values as its input**
(v1 contract §11). It may share the strict source-quartet loader and NPZ codec,
but must **not** call the report writer or `compare_cross_sitting` /
`compare_published` to obtain expected cross values. It resolves the source
quartets' effect pairs itself and recomposes the §5 quantities through the pure
cross-core primitives; a writer/verifier mistake in pairing, context assembly or
serialization must not be shared through one orchestration path. It re-derives
from the **two committed quartets**, then compares:

1. **Re-verify both source chains** from the published bytes: for each side, README → JSON →
   NPZ/CSV, recomputing the JSON canonical-LF digest, the NPZ file-byte digest and the CSV
   canonical-LF digest — independently of the cross JSON's `provenance`. The cross JSON's recorded
   per-side digests must equal the recomputed ones, and each side's `checks_ok`/
   `artifact_checks_ok` must hold.
2. **Recompute the comparison** through the frozen rules: resolve each of the 72 keys by exact
   triple/`effect_id` match; assert the grid-vs-contrast function; take the two sides' support
   intersection and the native comparison knots inside it (no interpolation, no nearest-gate
   substitution); recompute `D`, the common-defined mask and the state pair; and recompute every
   `Diagnostics` scalar (`L`, `D̄`, `RMS(D)`, the sign composition and `A_sign`, the Pearson shape
   correlation, each side's numerical maximum and localized peak, the displacement and
   coincidence) and each `comparison_state`/`comparison_reason`/`label_state`.
3. **Compare element-wise**: every NPZ member (knots, difference, mask, both state arrays) against
   the recomputed comparison; every CSV scalar against the recomputed `Diagnostics`; every
   comparison record's identity, `comparison_state`, `comparison_reason`, `label_state` and
   `npz`-membership against the recomputed result; every nonvalue row against the recomputed
   typed-empty; and each side's context quotation against that side's own **committed CSV cell**.
   A typed-empty row requires the recomputed reason and side.
4. **Check the invariants the writer could get wrong silently**: `defined[i] == 1` exactly where
   `state1[i] == 0` and `state2[i] == 0`; `difference[i] == 0.0` (placeholder) exactly where
   undefined; strictly increasing knots; `knots_mm` inside `support_mm`; `comparison_knot_count`
   equals each member's `(Kc,)` shape; the recomputed `Diagnostics` satisfies
   `shape_defined_count == defined_count == |D|` (the second count is not serialized, §6); the
   member set equals `npz_members` exactly; a
   non-comparable comparison has no member and no nonvalue row; the repeat-context range keys are
   **absent** on every non-selected context; `comparison_state`/`label_state` stay separate and no
   `label_state` but `deferred-pending-review` is written; `repeat_context_identity_fully_established`
   agrees with the recomputed contexts and does not enter `ok`; and the two v1 quartets are
   **byte-unchanged**.
5. **Check the digests last**: recompute the cross NPZ's file-byte SHA-256 and the cross CSV's
   canonical-LF SHA-256 against the cross JSON, then the cross JSON's canonical-LF SHA-256 against
   the cross README. A digest check is a *last* check, not the whole verification: a matching digest
   over wrong numbers is still wrong, so steps 1–4 must pass on their own.

## 13. What this schema does not decide (no new scientific rule)

The schema fixes **serialization only**. It invents **no** threshold, floor, optimum, `p`-value,
causality or population claim, **no** recurrence label rule, **no** resolvability rule, **no**
coarser-lattice grid mapping, and **no** change to any operator, precision or reduction. Every
number is the backend's; every state and reason is the backend's closed vocabulary; every typed
empty is the backend's own definedness rule. It adds no observable and estimates no new endpoint.

## 14. Review boundaries and deferred choices

The current artifact rules above are closed. The following are either future
scientific decisions outside this schema or deliberate serialization choices for
review:

1. **The recurrence evidence rule (`label_state`).** No explicit, pre-registered, metric-specific
   evidence rule is registered, so `label_state` is `deferred-pending-review` and no `recurs
   descriptively` / `does not recur descriptively` verdict is emitted (prespec §8). What rule would
   resolve a label, on which endpoint and at what like-for-like threshold, is a scientific
   question. This schema publishes the field and nothing else.
2. **`not resolvable with this design`.** The vocabulary is closed to include it, but no
   endpoint-specific resolvability rule exists, so it is never emitted (prespec §7). Whether a rule
   should exist is a prespec question.
3. **The §6 repeat-context identity gap is already decided for this version.** The
   published `repeats` groups carry no structured achieved-condition fields, so
   `e8`/`e64`/`e128` anchors are typed `repeat-context-identity-unverifiable`
   with no numerical range. This **satisfies** the amended prespec §11.8 test gate;
   it neither blocks publication nor changes `ok`. A future quantitative use of
   anchor variation would need a separately reviewed provenance addendum, not a
   job-name shortcut or a rewrite of the two frozen quartets.
4. **The unverifiable reason token (reconciled in this PR).** The merged backend
   (`sparse_sa5_cross_models.REASON_REPEAT_UNVERIFIABLE`) names the reason
   `anchor-members-whole-achieved-condition-is-not-published-in-the-quartet`. The prespec §6
   previously wrote the token as `repeat-group-member-achieved-condition-not-published`; that prose
   token has now been **corrected in the prespec to the backend's canonical value**, so the prespec
   and the code agree and no discrepancy remains. This contract publishes the **backend's** value
   (`reason` is copied verbatim, §5.4). The correction is a token-name documentation fix only: it
   changes **no scientific rule**, no state, no membership and no byte that a reader keys on.
5. **The grid-mismatch mapping.** If the two knot sets are not equal within `GATE_TOLERANCE_MM`,
   the pair is `not comparable` with reason `grid-mismatch-pending-review`; **no** coarser-lattice
   or nearest-native mapping is applied (prespec §3). Whether such a mapping is admissible, and its
   rule, is left open.
6. **Placement of the two oriented effect profiles.** This contract stores only `D` in the cross
   NPZ and leaves `E1`/`E2` in their own quartets (§3.2), so no within-sitting value has a second
   home. Whether a reviewer would prefer the two sides' values echoed as members (accepting the
   duplication under the source digest) is a serialization choice re-openable at review; it changes
   no number.
7. **Signed-zero handling.** This contract **preserves** IEEE signed zeros (§9) rather than
   normalizing them. If a future decision prefers normalization, it must be applied identically by
   the writer and §12's verifier, and is a serialization amendment.
8. **`empty-common-support` vs `side-wholly-undefined`.** Both are distinct backend reasons; the
   schema publishes them unchanged. Whether the distinction should be ranked or one subsumed is a
   prespec question, not a schema one.

## 15. Out of scope

No schema change to the v1 within-sitting contract; no writer, generator or committed array in this
PR; no Stage-2 pooling, no third sitting, no `p`-value, floor, optimum, causality or population
claim; no recurrence verdict; no agreement value. SA3/POD, SA6 UI and CFD alignment remain separate
evidence-driven slices. A v1 quartet and every frozen WP/SA2.4 report stay byte-untouched.
